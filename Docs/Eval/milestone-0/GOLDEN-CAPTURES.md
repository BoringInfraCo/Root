## Surprises beyond the three gaps

- **Denial semantics inversion**: `deny` rules never surface as error events — the tool disappears from the model's toolset (model-visible removal; captured literally in the model's own emitted text). The "rule-denied" error family is only reachable as the *ask*-deny message (`The user rejected permission to use this specific tool call.`), produced by `permission.asked` + the run loop's auto-reject. Adapters seeding deny-rules for fixture determinism must expect **no event at all** for denied tools that are never re-requested, unlike the contract's §5.1/§6 wording.
- **`tokens.reasoning` populated with thinking off** (cap 1: 175; cap 7: 8) — no `reasoning` events are emitted (correct), but step_finish token buckets still count provider-side reasoning spend. Fixtures must not infer thinking-mode from token buckets.
- **`exit 0 + empty stderr + zero stdout`** was plausible only as a watchdog artifact in caps 6/6b (killed before any model response) — noted as a harness-must-handle shape: a killed run can produce *no* stream content.
- **Signal hygiene**: `opencode run` at 1.18.27 does not handle external SIGINT at all (neither an idle stream nor mid-tool); SIGTERM kills the process but *not* its tool children. Non-interactive harness time bounds must SIGTERM → reap children (SIGKILL the tree), then parse the truncated NDJSON.
- **`state`-level schema placement** (`metadata`/`title`/`time`) differs from contract §3.2's part-level reading — fixtures above freeze the live shape.
- The `.env.d`? none; `node-compile-cache` + one generated dylib per capture under scratch TMPDIR as §4 documented, `state/opencode/locks/` empty post-exit, `data/opencode/opencode.db{,-wal,-shm}` under XDG data (except `:memory:`).
